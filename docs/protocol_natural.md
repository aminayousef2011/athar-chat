# Pre-registered evaluation on natural, independent phrasing

Registered 2026-10-26, before any contributor message used here has been labelled and before any
system has been run on one. The git commit that adds this file is the registration timestamp.
Changes after registration are appended to the log in section 10, with their date and reason.

## 1. Why

The locked test (docs/report.md) was written by one person, the project author, from a small set of
sentence frames, and that person also wrote S1's lexicon. This evaluation asks whether the main
results hold on requests written by **independent native speakers** for the **same scenarios**. It
also tests improvements specified here in advance, so that any gain is a result rather than a post
hoc estimate.

Questions:
1. Does the ranking of the frozen systems hold on independent phrasing? (N1)
2. Does the shared-core fix found in the v1 error analysis improve STS on new data? (N2)
3. Does a hybrid of LLM argument extraction and the deterministic policy beat end-to-end LLM tool
   calling? (N3)

## 2. Data

**Sources.**
- Wave 2: the Google Forms generated by
  `athar-data form-script --cards contrib/scenario_cards.csv --manifest data/splits/manifest.json --split test --wave 2 --people 8 --out contrib/make_forms_wave2.gs`
  (8 forms, about 15 requests each, covering the 71 test-family scenario cards once).
- The wave-1 block-5 form export (`data/raw/private/contrib/`), after screening (section 3).

**Collection window.** Wave 2 closes **2026-11-02 23:59 (Cairo)**. Responses after that are not used.

**Scenario cards.** Messages on cards whose scenario family is in the test split form the
**confirmatory set**: no system was trained on those scenarios. Messages on cards whose family is in
train or dev (6 of the block-5 cards) are reported separately and are not in any hypothesis test.

**Who is excluded.** The project author's own submissions. Before labelling starts, the author
records in section 10 whether the block-5 submission with contributor code `1` is the author's own;
if it is, it is excluded.

**Privacy.** Contributor texts stay in `data/raw/private/` (not committed) until the dataset is
frozen; the released dataset carries contributor codes only, as the consent text states.

## 3. Screening (before labelling)

Every export is screened with `athar-data check-contrib` (`athar.data.contrib.check_contrib`, rules
in `SCREEN_RULES`), with the dataset and the assistant drafts as references:

| Rule | Unit | Excluded when |
|---|---|---|
| M1 | message | ≥ 0.90 similar to another submission's answer to the same question |
| M2 | message | contains a written year or an English gloss in parentheses |
| M3 | message | version B identical to version A (B is dropped, A kept) |
| M4 | message | ≥ 0.90 similar to an existing dataset or draft text |
| R1 | submission | answers ≥ 0.85 similar on average to another submission |
| R2 | submission | more than a third of its messages flagged by M1, M2 or M4 |
| R3 | submission | the author's code, or a repeated submission of the same code (the first is kept) |
| R4 | submission | version B identical to A in more than a third of its pairs |

**Disclosure.** These rules were written on 2026-10-26 after inspecting the block-5 export, in which
most submissions were not independent writers (19 of 21 early submissions shared one writing
pattern; several codes gave identical answers). They apply unchanged to every later response. On
that export they keep 59 messages from 2 writers (41 on test-family cards). The analyst saw those
texts during screening; no system output has been computed on any contributor text.

## 4. Labelling and gold

1. `athar-data import-contrib` builds a blind sheet from the kept messages (no card plans).
2. The author labels every item with the annotation guide, unchanged since contract v1.0.
3. Ibrahim (second annotator) labels every item independently from a fresh blank sheet. κ is
   reported for intent and route, with target-set and argument agreement.
4. Disagreements are adjudicated by discussion and recorded **before any system is run** on the set.
5. `athar-data build`, `validate --strict` and a hash-locked manifest freeze the gold labels.
   Nothing changes after the freeze.

## 5. Systems

**Frozen v1 systems (unchanged; the v1 freeze must still verify):** S1, S2, S3, the oracle; S4 with
Jais 2 8B, Jais-3-7B, Jais-3-3.7B, Nile-Chat 4B and Qwen3 8B (primary 6-shot `prior`; inline
exemplars secondary); S7 (3 frozen seeds, `prior`); S8 (3 seeds, settings as in the locked run).

**v2 systems, specified here.** Their code is committed and hashed **before labelling starts**
(2026-11-03). Anything not ready by then is dropped and not reported. They live in new modules, so
the v1 files and their freeze stay unchanged.

- **Core v1.1** (shared extractor), from the v1 error analysis (docs/report.md, section 7.3):
  1. request framing also covers the want-verbs «عايز, عاوز, عايزه, عايزة, محتاج, محتاجه, محتاجة» and
     the spellings «اعمللي, اعملّي», each only when directly followed by a tool noun («تذكير», «منبه», …);
  2. fillers removed from reminder text also include «كده», «لو ينفع», «لو تقدر», «لو عندك وقت»,
     «بعد اذنك»;
  3. a day-period word inside a purpose clause (after the first «عشان/علشان») is not read as a time
     expression when a clock time occurs before that clause.
- **S1 v1.1**: S1 with core v1.1, plus the out-of-scope verbs missed on the v1 test: deletion
  «الغيلي, الغيلى, لغيلي»; modification «قدم», «أخر/اخر/أخّر», and «خلي» when directly followed by a tool
  noun.
- **S2-gcv, S3-gcv**: S2/S3 with core v1.1. The grid is that of `configs/train.yaml`; selection is
  by 5-fold `GroupKFold` over train+dev families on intent macro-F1 (ties: smaller C, then shorter
  n-grams); refit on train+dev. Ungated.
- **S9 hybrid** (computed from each S8 seed's stored output; no extra GPU run):
  - S8 declines → ABSTAIN;
  - otherwise the intent is the tool S8 names (its create call, or the `tool` of its
    `ask_clarification`); if S8 answered in plain text, the intent is S1 v1.1's;
  - the route comes from the deterministic policy on the core-v1.1 extraction: any blocking gap →
    CLARIFY with those targets;
  - otherwise ACT, with S8's datetime and reminder text when S8 made the matching create call, and
    the core-v1.1 extraction's otherwise.
- **Oracle v1.1**: gold intent with core v1.1 (the new ceiling).

Descriptive only: S4 and S7 rebuilt with core v1.1 from their predicted intents.

## 6. Metrics

Safe Task Success (STS) exactly as in the v1 protocol, with success by gold route, unsafe execution
split into text-only mismatches and genuinely wrong executions, and intent accuracy. Multi-seed
systems (S7, S8, S9) use each item's mean success over seeds as its score in paired tests.

## 7. Hypotheses and statistics

**Confirmatory (Holm over the three, α = 0.05), on the confirmatory set:**

| | Comparison | Expected direction |
|---|---|---|
| N1 | S1 vs S2 (frozen v1) | S1 > S2 (replicates H1) |
| N2 | S1 v1.1 vs S1 (frozen v1) | v1.1 higher |
| N3 | S9 vs S8 (seed means) | S9 higher |

**Tests.** Paired approximate randomization swapping whole scenario cards (10,000 permutations);
95% card-level bootstrap intervals (10,000 resamples); exact McNemar as sensitivity. With at least 5
independent writers, a writer-clustered test is added as sensitivity, and leave-one-writer-out STS is
reported for every system.

**Minimum size.** If the confirmatory set has fewer than 60 items or fewer than 3 independent writers
after screening, no hypothesis is tested and everything is reported descriptively.

**Descriptive:** every other system and comparison; the training-scenario subset; and the paired
author-vs-contributor comparison: on the cards both wrote, each system's STS on the author's locked
test items vs the contributors' items.

## 8. One run

- CPU systems are scored once by a committed command after the gold freeze.
- GPU systems are scored by notebook commits on Kaggle (2× T4) with a `natural` evaluation set,
  rehearsed on CPU with tiny models first.
- Outputs go to `results/natural/`. A failed GPU commit may be re-run unchanged; a changed one is a
  deviation and is logged.
