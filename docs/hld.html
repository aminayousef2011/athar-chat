ATHAR Chat architecture

How one Egyptian Arabic request becomes an ACT, CLARIFY or ABSTAIN response, and how the offline pipeline builds and judges the three intent systems without touching the locked test set.

shared, identical for every system varies per system (S1 / S2 / S3) optional, exploratory, outside the core claims

Invariants the code enforces

  • Classifiers predict one of three intent labels (create_reminder, create_alarm, unsupported). They never predict the route. The policy derives the route.
  • The system never invents a value. A missing date uses the next-occurrence rule from the contract. Anything else unresolved becomes a clarification target.
  • Vocabularies, hyper-parameters, keyword lists and extraction rules are frozen before the test split is opened once, in week 6.
  • Splits are made by scenario family, so paraphrases and complete/incomplete pairs never cross between train, dev and test.
  • Tools are simulated. An ACT response is a JSON call record and nothing is scheduled.
